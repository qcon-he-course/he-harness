# PC-302: Two pets added to one owner at the same moment can lose one

**Status:** open

**Type:** defect, older than the change that found it.

## What happens

Two requests add a pet to the same owner at the same moment. Both succeed. Afterwards the owner has only one new pet: the other row is still in `pets`, with `owner_id` set to null, so it no longer appears on the owner's page. The same race lets two pets with the same name be added to one owner, because the first pet is already detached when the second is saved.

## Why it is here

`PetClinicConcurrencyTests.twoSimultaneousAddsWithTheSameName` checks this and passes or fails by timing. Until the defect is fixed, the test runs in the known-defect lane: shown on every run, not counted in the build.

## Closing it

Fix the defect, set the status to closed, and remove the test's line from `known-defect-tests.txt`. The test then runs in the build again.
